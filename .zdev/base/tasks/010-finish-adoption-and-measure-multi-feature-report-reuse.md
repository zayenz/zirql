# Finish adoption and measure multi-feature report reuse

## Outcome

Both tools have documented shared ownership, compatible public query behavior and measured bounded report reuse, with redundant evaluators removed.

## Context

Read the completed integration results and live consumer records. Reconcile Zincite base-126/base-127/base-128 against demonstrated CLI/library outcomes, not core feature names. Start from existing Zincite query-acceptance and Zirium query-profiling drivers. Finish Zincite's legacy pipeline edit adapter through the shared effect boundary while retaining validated candidate semantics; remove only proven-redundant common implementations.

## Boundaries

- No crate publication, GitHub visibility change, unrelated cleanup, permanent instrumentation, persistent cache or automatic budget relaxation.
- Use named small syntax, semantic and literal-data cases; no corpus sweep, timing assertions or benchmark service.
- Do not mark consumer tasks complete without their own required acceptance evidence; preserve existing selected work and independent commit histories.

## Done when

- [ ] All existing query entry points, including Zincite legacy edits and Zirium builders/diff paths, use the agreed shared owner for applicable common execution.
- [ ] Documentation separates framework guarantees, host policy, native result types and implemented versus deferred syntax with complete examples for both frontends.
- [ ] Equivalent one-program and separate-request reports have equal outputs/statuses; temporary instrumentation demonstrates parse/fact reuse and records memory lifetime boundaries.
- [ ] Named measurements record revisions/environment, samples/spread, wall time and available peak memory; failed or limit-rejected cases are reported separately.
- [ ] Only redundant language implementations are removed, host contracts remain compatible, consumer zdev records reflect actual outcomes, and all affected repositories have attributable committed results.

## Validation

- Run existing host query suites and required checks once after final integration; broaden only for new failures or unresolved concerns.
- Use existing measurement drivers or a small adaptation, inspect output/status parity and report unavailable memory evidence explicitly.
- Run git diff --check and zdev validation in each area whose records change; documentation-only changes need no new tests.
